# Fleet Review — 2026-11-27

Full review of every fleet repo (stacks + the two Kotlin projects) against the code on disk at 2026-11-27. Supersedes [audit.md](audit.md). Severity per finding: **[HIGH]** fix before next deploy-relevant change, **[MED]** fix soon, **[LOW]** hygiene. File:line refers to the stack repo.

## Fleet Changes

- **media-stack — deleted from GitHub 2026-11-27.** Legacy combined Jellyfin+Immich deployment, long superseded by `jellyfin-stack` + `immich-stack`; its compose still registered tailnet node names `jellyfin`/`immich` owned by the production stacks. No longer listed anywhere as active.
- **inference-stack — retired 2026-11-27** (repo deletion in progress). Pre-fleet-era rootful Docker attempt at GPU LLM serving, superseded by `radiance-stack`. Violated current conventions on multiple axes: Docker not podman, root-run, the shared SOPS age private key mounted *into containers*, `NET_ADMIN` + `SYS_MODULE`.
- **freya + radiance-stack are live.** `fleet.yaml` now lists host `freya` and the `radiance` stack; `https://radiance.tail6a7569.ts.net` serves with passing serve/health tests (the README "authkey pending / sidecar down" footnote was stale and has been corrected).

## Secrets Posture (fleet-wide)

**No plaintext secret values are committed in any repo's tree or history.** `turnstone-stack-secrets` is correctly SOPS+age encrypted end to end. Everything below is a handling problem, not an exposure problem.

## Cross-Cutting (Fleet-Wide)

1. **`$(STACK_NAME)` used but undefined** in the Makefiles of jellyfin/immich/ha/dozzle — the `service-status`/`install-service` echoes expand to empty unit names (`systemctl --user status .service`). Define `STACK_NAME` or use `$(STACK)-stack`.
2. **`${PODMAN_SOCKET}` interpolated with no default** in the jellyfin/immich/dozzle/authentik/synapse composes — compose config breaks for anyone without it in `.env`. The `:-/run/user/<uid>/…` default pattern exists elsewhere (and defaults to jellyfin's uid 1003 — see ha/dozzle notes).
3. **Unnecessary `cap_add: NET_ADMIN` on userspace-mode tailscale sidecars** (jellyfin, immich, ha, ca). `TS_USERSPACE="true"` needs no net_admin; dozzle-stack's sidecar proves it works without. ca additionally mounts `/dev/net/tun` for no reason.
4. **`security_opt: label=disable` on app containers in the media group** (jellyfin-stack compose:109, immich-stack, ha-stack compose.template:109; other stacks don't set it). A blanket SELinux unconfine is a fleet decision to make **once** — radiance-stack demonstrates the confined alternative (default seccomp profile plus exactly the io_uring/NUMA calls needed, `seccomp-radiance.json`).
5. **`setup.sh` missing `set -euo pipefail`**: dozzle-stack (whole script — and it writes sudoers, keys, and does `rm -rf`), dns-stack, server-stack root phase, turnstone `setup.sh`/`reset-secrets.sh` (have `set -e` only; add `-u -o pipefail`).
6. **Host-identity drift — `odin` (the old Debian box) persists**: turnstone-stack README claims host `odin`, blueprints hardcode an `odin-turnstone` redirect URI, `TURN_EXTERNAL_IP` shipped as a placeholder; dns-stack carries a Debian `apt-get remove dnsmasq` leftover and hardcodes HA backend `192.168.1.84`; ca-stack says "proven on tva" in a compose comment. And `fleet.yaml` ignored host `freya` entirely until this review.
7. **Backup story missing for the stateful stacks**: immich (named volume `pgdata`; teardown runs `down -v`) and ha (teardown deletes `./ha/config` outright, while its README:70 says "back up this directory"). Both need `make-backup` targets before anything else happens to them.

## Per-Stack Findings

### radiance-stack — CLEAN (conventions exemplar)

The reference implementation: fail-closed selfheal, real test suite, user-level unit, nologin user, recursive state ownership.

- **[LOW]** Real tailnet name `tail6a7569.ts.net` hardcoded as the shipped default (`.env.example:40`, `setup.sh:399`) — identifier leak from a public repo; ship a placeholder.

### turnstone-stack — MOST PROBLEMATIC repo

Half-finished Docker→podman migration; the podman path has never been run end to end.

**[HIGH]**

1. Weak hardcoded TURN secret fallback (`docker-compose.yml:216,263` — `${TURNSTONE_TURN_SECRET:-turnstone-turn-secret}`), and `setup.sh:281` renders an **empty** `turn_shared_secret` into `homeserver.yaml` (the heredoc references the host env var, which the render environment never sets).
2. `reset-secrets.sh` / `setup.sh` decrypt secrets into repo-dir temp files `.tmp_decrypted.yaml` / `.tmp_plain.yaml` (`setup.sh:26,476`, `reset-secrets.sh:25,130`) with default umask, and `.gitignore:31` (`.tmp_decrypted`) matches **neither name** → a `git add -A` commits plaintext.
3. Provisioning hard-requires Docker (`setup.sh:37-44` aborts without docker/docker compose) — `make setup` **cannot run at all** on the podman-only fleet.
4. `podman-compose.yml` interpolates `PGUSER`/`PGPASSWORD`/`COUCHDB_*` defined nowhere (:78-79, :363-364) and mounts secret/config paths `setup.sh` never creates (different names, wrong `homeserver.yaml` path). Under rootless podman, missing bind sources become empty dirs instead of errors.
5. Sidecar lacks `TS_CERT_DOMAIN` → `serve-config/serve.json` keys expand empty; the serve config also uses an obsolete schema.
6. `blueprints/hermes-oidc.yaml:39` hardcodes the `odin-turnstone` redirect URI; `post-authentik-blueprint.sh` seds a placeholder that no longer exists (silent no-op).
7. `podman-compose.yml:162` typo `SYNAPHE_SERVER_NAME` → Synapse never receives `server_name`.
8. `nginx-rtc.conf:28` `proxy_pass http://127.0.0.1:8008` is dead in the podman netns (needs `synapse:8008`). Also: `Dockerfile.synapse-rtc-foci` adds nothing, and the dashboard proxies `/.well-known/matrix/`, shadowing the committed `client.json` — both MatrixRTC-FOCI mechanisms are inert. `hermes-stack` sets `HERMES_CONFIG=/app/config.yaml`, outside its own mount (`./hermes_config:/app/config`). `openscad-api` ignores the request `timeout` (unbounded CPU per request, no output cleanup) — no command injection, but unbounded.

**[MED]** secrets duplicated into 644 config files; legacy `docker-compose.yml` (NET_ADMIN, `/dev/net/tun`, 17 `network_mode: container/service`, `${HOME}` mounts) should be deleted; coturn env vars the image ignores + `0.0.0.0` binds contradicting the compose header; dozzle socket hardcoded `/run/user/1000` (`podman-compose.yml:308`); `CURL_CA=-k` on the Authentik bearer-token call; no root systemd unit / stack user / fleet Makefile targets; `wiki/` is stale Docker/WSL documentation.
