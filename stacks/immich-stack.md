# immich-stack

Self-hosted photo library (Immich). Own Tailscale node **`immich`**; UI at `https://immich.<tailnet>.ts.net`. Split out of the deprecated `media-stack` on 2026-10-17.

## Role in the Fleet

Self-hosted Google Photos alternative — photo/video library with metadata extraction, facial recognition, and backup from mobile clients. Uses PostgreSQL (with pgvector for ML features) and Valkey/Redis for caching. Photos/videos live on network storage; database stays on local disk.

## Services

| Container | Image | Role |
|---|---|---|
| `immich-tailscale` | `tailscale/tailscale:v1.102.5` (pinned) | Userspace tailscaled + SERVE (:443 → immich-server, raw TCP :7007 → dozzle-agent). `TS_USERSPACE: "true"` — kernel TUN mode is not reliable in rootless netns. |
| `immich-immich-server` | `ghcr.io/immich-app/immich-server:release` (tag from `.env`) | The photo library server. Photos/videos on `/mnt/samba_storage/Immich` (CIFS bind mount). Depends on redis, database, and tailscale. DB password via file mount (`DB_PASSWORD_FILE`). |
| `immich-redis` | `valkey/valkey:9` (digest-pinned) | Cache/session store for Immich. Ephemeral — data is rebuilt from the database on restart. Healthcheck: `redis-cli ping`. Pinned by digest to avoid breaking changes. |
| `immich-postgres` | `ghcr.io/immich-app/postgres:14-vectorchord0.4.3-pgvectors0.2.0` (digest-pinned) | PostgreSQL 14 with pgvector extension for ML features. Data in named volume `immich_pgdata` on local disk. Password via file mount (`POSTGRES_PASSWORD_FILE`). `--data-checksums` enabled for data integrity. |
| `immich-dozzle-agent` | `amir20/dozzle:latest` (`agent`) | Reports this stack's containers to the central Dozzle hub over mTLS gRPC on :7007. |

No host ports — everything is exposed through Tailscale SERVE only.

## Data

| Data | Location | Type |
|------|----------|------|
| Immich photos/videos | `/mnt/samba_storage/Immich` (CIFS bind mount) | Network storage — host dir must exist before `make up`. CIFS ownership is a no-op; access is via the stack user. |
| PostgreSQL data | Named volume `immich_pgdata` (local disk) | Local disk only — databases do heavy fsync and file-locking that network shares handle poorly |
| Valkey/Redis | Ephemeral container storage | Cache/session store — rebuilt from database on restart |
| Tailscale node state | `./ts_state/state.soc` bind mount | Persistent identity — migrated from media-stack, DO NOT delete |

## Secrets

| File | Source | Used By |
|---|---|---|
| `.tailscale-authkey` | Copied from `$STACK_ENV_DIR` by setup | Tailscale sidecar auth (entrypoint reads it into `TS_AUTH_KEY`) |
| `.dozzle-cert.pem`, `.dozzle-key.pem` | Copied from `$STACK_ENV_DIR` (generated once by dozzle-stack) | Dozzle agent mTLS credential |
| `.db_password` | Generated by setup (`openssl rand -hex 32`) | PostgreSQL + Immich server via `*_PASSWORD_FILE` mounts. On an already-initialized data volume this is only used for superuser login; the catalog keeps its own copy. |

## SERVE Config

```json
{
  "TCP": {
    "443": { "HTTPS": true },
    "7007": { "TCPForward": "immich-dozzle-agent:7007" }
  },
  "Web": {
    "${TS_CERT_DOMAIN}:443": {
      "Handlers": {
        "/": { "Proxy": "http://immich-server:2283" }
      }
    }
  }
}
```

Routes `https://immich.<tailnet>.ts.net` → immich-server container on port 2283. Raw TCP :7007 forwards to the dozzle agent for log collection.

## Operations

Standard Makefile targets apply. Additional immich-specific:

| Target | Description |
|--------|-------------|
| `immich-health` | Probe the Immich server healthcheck endpoint (`healthcheck.sh`). Useful after startup or upgrade. |
| `immich-gen-secret` | Append a generated `DB_PASSWORD` to `.env`. Use if resetting the database. |

## Resetting the Database

If Immich won't start after changing `DB_PASSWORD`:
```bash
make down
sudo -u immich podman volume rm immich_pgdata   # check exact name with 'podman volume ls'
make local-setup    # regenerates .db_password
make up
```

## Moving Data to Samba Drive

To migrate an existing named volume to the network share:
```bash
make down
sudo -u immich podman run --rm -v <volume_name>:/src:ro -v /mnt/samba_storage/Immich:/dst alpine cp -a /src/. /dst/
sudo -u immich podman volume rm <volume_name>
make up
```

## Gotchas

- PostgreSQL data stays on local disk (named volume). Never bind-mount the DB to a network share — heavy fsync and file-locking make CIFS unreliable for databases.
- Photos/videos are a bind mount to `/mnt/samba_storage/Immich` — the directory must exist before `make up`. If you mount a new Samba share, re-run `sudo make setup` or create it manually first.
- `security_opt: label=disable` is required on rootless Podman for bind mounts that cross SELinux contexts (both the CIFS drive and podman socket).
- Redis (Valkey) and PostgreSQL are both digest-pinned — run `make upgrade` to pull newer images, which triggers a full down/up cycle.
