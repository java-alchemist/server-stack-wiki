# dozzle-stack

Central container log viewer hub. Own Tailscale node **`dozzle`**; UI at `https://dozzle.<tailnet>.ts.net`.

## Role in the Fleet

The Dozzle stack is the fleet's centralized logging endpoint. It runs a Dozzle **hub** (server mode) that dials out to per-stack dozzle agents over mTLS gRPC on port 7007, collecting logs from every container across all stacks into one web UI.

It also generates and owns the shared mTLS certificate pair (`dozzle-cert.pem`/`dozzle-key.pem`) that every other stack's agent uses for authentication. This pair is copied to `$STACK_ENV_DIR/` during dozzle-stack setup, then each stack copies its own copy from there into `secrets/`.

## Architecture

```
client browser ──→ https://dozzle.<tailnet>.ts.net (SERVE :443 → hub :8080)
                      │
                 dozzle-hub (server mode, no podman socket of its own except local)
                      │
          mTLS gRPC dial-out on :7007 to each agent:
          ├─→ dns.<tailnet>.ts.net:7007      | "dns"
          ├─→ jellyfin.<tailnet>.ts.net:7007  | "jellyfin"
          ├─→ immich.<tailnet>.ts.net:7007    | "immich"
          └─→ [any new stack's agent]         | "<name>"
```

- The hub dials OUT — agents don't need inbound firewall rules.
- Each **agent** runs inside its own stack and reads that stack's rootless podman socket (per-user isolation: no cross-stack socket access).
- The hub also watches its own local engine (`./data` + local podman socket) so it shows at least one host even if all remote agents are offline (Dozzle v11 fatals on zero hosts).

## Services

| Container | Image | Role |
|---|---|---|
| `dozzle-tailscale` | `tailscale/tailscale:latest` | Userspace tailscaled + SERVE (:443 → hub, raw TCP :7007 not needed — hub is the endpoint) |
| `dozzle-hub` | `amir20/dozzle:latest` (server mode) | Central log viewer. Reads local podman socket + dials remote agents via mTLS gRPC. Simple auth against pre-seeded `data/users.yml`. API exposed on loopback only (`127.0.0.1:8460`) for operator tooling. |

Note: no dozzle-agent in this stack — the hub reads its own containers through the local podman socket mount.

## Data

| Data | Location | Type |
|------|----------|------|
| Dozzle settings (`dozzle.yml`) + users (`users.yml`) | `./data/` bind mount (ro) | Generated by setup, survives container restarts |
| Tailscale node state | `./ts_state/state.soc` bind mount | Persistent identity — DO NOT delete |

## Secrets

| File | Source | Used By |
|---|---|---|
| `.tailscale-authkey` | Copied from `$STACK_ENV_DIR` by setup | Tailscale sidecar auth |
| `.dozzle-cert.pem`, `.dozzle-key.pem` | **Generated ONCE** by this stack's bootstrap (ed25519 self-signed CA, 5-year validity), copied into `$STACK_ENV_DIR/` and `secrets/` | mTLS credential shared with every agent. THE KEY IS THE CREDENTIAL — anyone holding it can read all agents' logs. Never commit, never share-mount across stacks. |
| `.dozzle_password` | Generated by setup (random bcrypt) | UI login password for simple auth |
| `.hermes_password` | Generated by setup (random bcrypt) | API access for operator/agent tooling via `make jwt` |

## SERVE Config

```json
{
  "TCP": {
    "443": { "HTTPS": true }
  },
  "Web": {
    "${TS_CERT_DOMAIN}:443": {
      "Handlers": {
        "/": { "Proxy": "http://dozzle:8080" }
      }
    }
  }
}
```

Routes `https://dozzle.<tailnet>.ts.net` → hub container on port 8080. Tailscale handles TLS termination using the cert domain from `TS_CERT_DOMAIN`.

## Agent Registry

Agent endpoints are registered per-stack in `$STACK_ENV_DIR/dozzle-agents.d/<stack>` (one file per stack, format: `<node>.<tailnet>.ts.net:7007|<name>`). The hub's Makefile reads all files from this directory via `AGENT_LAYER` and assembles them into the `DOZZLE_AGENTS` env var on every `make up`. To add a new stack's agent, that stack's own `setup.sh` writes its registration file — no manual edit of dozzle-stack's `.env` is needed.

## API Access (Operator Tooling)

The hub exposes a REST API on loopback only (`127.0.0.1:8460`) for operator tooling over SSH:

```bash
make jwt   # prompt for hermes password → JWT to ~/.cache/dozzle/token
curl -sk -H "Authorization: Bearer $(cat ~/.cache/dozzle/token)" \
     http://127.0.0.1:8460/api/hosts/<host>/containers/<id>/inspect
```

The token has no expiry by design (`DOZZLE_AUTH_TTL` unset → session mode). It dies only when `users.yml` or the session secret changes. If you ever set `DOZZLE_AUTH_TTL`, it must be a Go duration with unit suffix (`720h`) — bare seconds crash hub startup.

## Operations

Standard Makefile targets apply. Additional dozzle-specific:

| Target | Description |
|--------|-------------|
| `jwt` | Generate API bearer token (prompts for hermes password, writes to `~/.cache/dozzle/token`) |
| `manifest` | Show the central shared-env manifest (which stack reads which file) |

## Gotchas

- The hub's healthcheck uses exec-form (`/dozzle healthcheck`) — the image is scratch-based with no shell. podman-compose wraps healthchecks in `/bin/sh -c`, so we skip it entirely and rely on `restart: unless-stopped` + logs.
- Agent reachability rides each stack's userspace Tailscale sidecar delivering inbound to its bridge network (`<node>.ts.net:7007`). If a future Tailscale version stops forwarding non-SERVE ports, fallback: publish `127.0.0.1:<port>:7007` in the agent stack and point the hub at the host's tailnet IP instead (loses node-name portability).
- To change the UI password: regenerate via `cat secrets/.dozzle_password | podman run --rm -i --entrypoint /dozzle amir20/dozzle generate dozzle > data/users.yml` then `make restart`.
