# dns-stack

Pi-hole DNS resolver + Caddy HTTPS reverse proxy. Own Tailscale node **`dns`**.

## Role in the Fleet

The DNS stack provides two core infrastructure services:

1. **Pi-hole** — Local DNS resolver with ad/tracker blocking and custom `.home.arpa` records for hostname resolution on the tailnet. All other stacks' tailscale sidecars route through this for DNS queries.
2. **Caddy** — HTTPS reverse proxy that routes traffic by hostname to services behind it (e.g., dashboard, web UIs not served directly via Tailscale SERVE). Listens on host ports `8443:443` and `8080:80`.

## Services

| Container | Image | Role |
|---|---|---|
| `dns-tailscale` | `tailscale/tailscale:latest` | Userspace tailscaled + SERVE (raw TCP :7007 → dozzle-agent). No HTTPS routes — Caddy handles that. Not managed by watchtower (no label). |
| `dns-pihole` | `pihole/pihole:latest` | DNS resolver, ad/tracker blocking, custom local records via dnsmasq config in `./pihole/dnsmasq.d/`. Published on `127.0.0.1:5053` (loopback). Managed by watchtower. A host-side dnsmasq forwarder bridges LAN port 53 → loopback :5053 for LAN clients and Unifi controller access. |
| `dns-caddy` | `caddy:2-alpine` | HTTPS reverse proxy. Routes by hostname per `./caddy/Caddyfile`. Host ports `8443:443`, `8080:80`. Let's Encrypt cert storage in named volumes. Managed by watchtower. |
| `dns-dozzle-agent` | `amir20/dozzle:latest` (`agent`) | Reports this stack's containers to the central Dozzle hub over mTLS gRPC on :7007. Managed by watchtower. |
| `dns-watchtower` | `containrrr/watchtower:latest` | Auto-updates labeled services hourly with rolling restart and rollback on healthcheck failure. Polls every 3600s. |

## SERVE Config

Routes Pi-hole admin UI via Tailscale HTTPS. Caddy still handles `.home.arpa` routes on host ports 8443/8080 for LAN access — they don't go through SERVE.

```json
{
  "TCP": {
    "7007": { "TCPForward": "dns-dozzle-agent:7007" }
  },
  "Web": {
    "${TS_CERT_DOMAIN}:443": {
      "Handlers": {
        "/admin/": { "Proxy": "http://pihole:80/admin/" }
      }
    }
  }
}
```

- `https://dns.<tailnet>.ts.net/admin/` → Pi-hole admin UI (via Tailscale SERVE)
- Port :7007 → dozzle-agent (raw TCP for mTLS gRPC log collection)

## Pi-hole v6 Notes

- Upstream DNS uses v6 FTL config via `FTLCONF_dns_upstreams` (semicolon-delimited list). Old JSON-bracket form crashes FTL startup (`bad port at line 33`).
- Local records now belong in `pihole.toml` (Web UI or `FTLCONF_dns_localRecords`). The legacy `/etc/dnsmasq.d/` bind mount is only read during the one-time v5→v6 migration.
- Password is read natively via `WEBPASSWORD_FILE=pihole_password` (the file path inside the container).

## Operations

Standard Makefile targets apply (`make setup`, `up`, `down`, `restart`, `upgrade`, `serve`, `status`, `logs`, `validate`, `teardown`).

### Re-apply SERVE routes

```bash
make serve   # restarts tailscale sidecar; re-applies serve.json for :7007 → dozzle-agent
```

## Gotchas

- Pi-hole DNS healthcheck uses `dig +short +norecurse @127.0.0.1 pi.hole` — if this fails, FTL isn't running or the named volume is stale from a v5 migration.
- Caddy binds on high ports (8443/8080) because rootless Podman can't bind below 1024. Clients reach via `https://<dns-node-ip>:8443`.
- No host port for DNS on the tailnet — clients reach Pi-hole via Tailscale node IP :53 (Tailscale MagicDNS routes to the right machine).

## LAN DNS Access (dnsmasq Forwarder)

Rootless Podman can't bind below port 1024, so Pi-hole is published on `127.0.0.1:5053` (loopback only). A host-side dnsmasq forwarder bridges standard port 53 → the loopback port for LAN access.

**Setup:** `make setup` automatically installs and configures dnsmasq via the `_bootstrap` phase if not already present. The forwarder listens on `127.0.0.1` and the LAN interface IP, forwarding all queries to Pi-hole at `127.0.0.1:5053`. It also disables systemd-resolved's DNS stub listener (`DNSStubListener=no`) which otherwise conflicts with dnsmasq on port 53 (systemd-resolved holds `127.0.0.53:53`, and the dnsmasq systemd wrapper adds `--local-service` which binds all of `127.0.0.0/8`).

**Unifi configuration:** In Unifi Controller → Settings → Networks → [LAN] → DHCP Server:
- **DNS 1:** `192.168.1.82` (Pi-hole via forwarder — primary)
- **DNS 2:** `1.1.1.1` (Cloudflare — fallback if Pi-hole is down)

**Teardown:** Removes the dnsmasq forwarder config and disables the service, but prompts before removing the dnsmasq package itself (other services may depend on it).
