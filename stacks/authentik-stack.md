# authentik-stack

Authentik identity provider (OIDC/SAML) for the fleet. Own Tailscale node **`authentik`**.
Standalone successor to the authentik service that lived inside `turnstone-stack`
(repo rebuilt 2026-10-24 to fleet conventions; deployed on tva).

## Role in the Fleet

Central identity provider — OIDC SSO for consumer stacks (hermes dashboard,
synapse/Element, future services). Issuer URL:
**`https://authentik.tail6a7569.ts.net/application/o/`**.

UI + API at `https://authentik.tail6a7569.ts.net`. First boot runs DB migrations
(40–60s); default superuser is **admin / changeme** (forced password change).

## Services

| Container | Image | Role |
|---|---|---|
| `authentik-tailscale` | `tailscale/tailscale:latest` | Userspace tailscaled + SERVE (:443 → server, raw TCP :7007 → dozzle-agent). Not managed by watchtower (no label). |
| `authentik-server` | `ghcr.io/goauthentik/server:${AUTHENTIK_TAG}` (`server`) | Web UI + API on :9000. Managed by watchtower (floating tag, rolling restart with rollback). Healthcheck probes `/-/health/`. |
| `authentik-worker` | same image (`worker`) | Background tasks (email, webhooks, scheduled flows). Managed by watchtower. |
| `authentik-postgresql` | `postgres:16-alpine` | Dedicated database in named volume `pg-data`. **Not** managed by watchtower — forward-only migrations; bump manually in lockstep with authentik releases. |
| `authentik-dozzle-agent` | `amir20/dozzle:latest` (`agent`) | Reports this stack's containers to the central Dozzle hub over mTLS gRPC on :7007. Managed by watchtower. |
| `authentik-watchtower` | `containrrr/watchtower:latest` | Auto-updates labeled services hourly with rolling restart and rollback on healthcheck failure. Polls every 3600s. |

No Redis — modern authentik (2024+) no longer requires one; upstream's compose
has none either. No docker-socket mount into the worker (upstream uses it for
automatic outpost deployment; outposts here are deployed manually if ever needed).

## Data

| Data | Location | Type |
|------|----------|------|
| PostgreSQL database (users, providers, applications) | named volume `pg-data` (`authentik-stack_pg-data`) | Back up before any teardown/re-clone |
| Media uploads + runtime state | `./authentik/data/` bind mount (700) | Local disk — back up this dir to preserve uploaded media |
| Tailscale node state | `./ts_state/` bind mount | Node identity — never delete |

## Secrets

| File | Source | Used By |
|---|---|---|
| `.tailscale-authkey` | Copied from `$STACK_ENV_DIR` by setup | Tailscale sidecar auth |
| `.dozzle-cert.pem`, `.dozzle-key.pem` | Copied from `$STACK_ENV_DIR` | Dozzle agent mTLS credential |
| `.pg_password` | Generated by `setup.sh local-setup` (`openssl rand -base64 36`) | postgres (native `_FILE`) + authentik (via `file://`) |
| `.authentik_secret_key` | Generated by `setup.sh local-setup` (`openssl rand -base64 60`) | server + worker Django signing key (via `file://`) |

**Authentik reads secret values through the `file:///…` scheme in env vars — the
`_FILE` suffix is silently ignored by authentik** (cryptic "Secret key missing"
errors otherwise). The postgres image does support native `_FILE`. Compose uses:
`AUTHENTIK_SECRET_KEY=file:///run/secrets/authentik_secret_key`,
`AUTHENTIK_POSTGRESQL__PASSWORD=file:///run/secrets/pg_password`.

## SERVE Config

```json
{
  "Web": {
    "${TS_CERT_DOMAIN}:443": { "Handlers": { "/": { "Proxy": "http://authentik-server:9000" } } }
  },
  "TCP": {
    "443": { "HTTPS": true },
    "7007": { "TCPForward": "authentik-dozzle-agent:7007" }
  }
}
```

- `https://authentik.<tailnet>.ts.net` → UI + API (the issuer base for all OIDC consumers)
- :7007 → dozzle-agent (raw TCP, mTLS gRPC log collection)

## Ops Notes

```sh
# Service account + API token for programmatic provider management:
bash scripts/init-service-account.sh sa-blueprints   # prints the token — save it in the CONSUMER stack's secrets/

# OIDC providers: create in UI (Applications → New Application), or import a
# blueprint from blueprints/ (edit redirect URIs first).
```

- **Postgres lockstep:** when an authentik release requires a newer PostgreSQL,
  bump `AUTHENTIK_PG_TAG` in `.env`, then `make upgrade`. Never let watchtower
  touch postgres (no label).
- **Version strategy:** `AUTHENTIK_TAG=stable` floats; watchtower auto-updates
  server/worker with rolling restart + rollback on healthcheck failure. DB
  migrations run automatically at boot.
- **`/dev/shm`:** podman-compose 1.0.6 ignores `shm_size`, so containers run
  with the default 64MB shared memory (upstream's docker compose sets 512mb).
  If authentik ever shows shm exhaustion in logs, add a workaround then.
- **Email:** no SMTP configured; email stages/alerts won't send until
  `AUTHENTIK_EMAIL__*` vars are added to `.env`.
